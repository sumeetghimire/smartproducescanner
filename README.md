# Smart Produce Scanner

A web app that identifies apples vs. bananas from an uploaded photo using a
CNN, estimates ripeness, and returns nutrition/usage info with spoken
(text-to-speech) output. Prototype built from the COMP6900 project scoping
document.

## Scope decisions vs. the scoping document

- **Dataset**: the scoping doc planned for 2,000+ user-uploaded images. For
  this prototype we instead sourced 4,522 real apple/banana photos from the
  public [Fruit-Images-Dataset](https://github.com/horea94/Fruit-Images-Dataset)
  (Mureșan & Oltean, 2018 — the same paper cited in the scoping doc's
  literature review), combining multiple varieties (Braeburn, Golden,
  Granny Smith, Red Delicious / Banana, Banana Red, Banana Lady Finger)
  into two flat classes.
- **Ripeness detection**: no labelled ripeness dataset (unripe/ripe/overripe)
  was reachable without Kaggle credentials, so ripeness is estimated with a
  documented HSV colour-analysis heuristic (`backend/app/ripeness.py`)
  rather than a second trained CNN. This is flagged in the API response
  (`ripeness_method`) and should be called out as a prototype limitation,
  matching the doc's own "extensions planned" section.
- Everything else (CNN classifier, confidence threshold rejecting unclear
  images, nutrition/usage info, spoken output, browser-based upload) follows
  the scoping document directly.

## Project structure

```
backend/
  app/            FastAPI application (inference, ripeness, fruit info, API)
  training/       Dataset prep + CNN training scripts
  models/         Saved model + labels (generated by training)
frontend/         Static HTML/CSS/JS upload UI (served by FastAPI)
data/raw/         Flattened apple/banana training images (generated)
data_src/         Sourced dataset repo (sparse checkout)
```

## Setup

```bash
pip install -r backend/requirements.txt
```

## 1. Prepare the dataset (already run for this repo)

```bash
python backend/training/prepare_dataset.py
```

## 2. Train the CNN

```bash
python backend/training/train.py
```

Saves `backend/models/fruit_classifier.keras` and `backend/models/labels.json`.

## 3. Run the web app

```bash
uvicorn backend.app.main:app --reload
```

Then open http://127.0.0.1:8000 — upload a photo of an apple or banana to
see the classification, ripeness estimate, nutrition/usage info, and click
"Listen to result" for spoken output.

## API

`POST /api/predict` — multipart file upload (`file` field), returns JSON:

```json
{
  "accepted": true,
  "label": "banana",
  "confidence": 0.98,
  "ripeness": "ripe",
  "ripeness_note": "...",
  "ripeness_method": "heuristic-colour-analysis",
  "info": { "nutrition": {...}, "health_benefits": [...], "usage_suggestions": [...] },
  "speech_text": "..."
}
```

Predictions below the confidence threshold (`CONFIDENCE_THRESHOLD` in
`backend/app/config.py`, default 0.70) are rejected with `accepted: false`.

## Next steps (see scoping doc §5.1)

- Replace the ripeness heuristic with a trained model if a labelled
  ripeness dataset becomes available.
- Expand beyond apple/banana to more fruit classes.
- Broaden the dataset with real-world (non-studio-background) photos to
  improve generalisation, per the doc's bias/fairness risk.
